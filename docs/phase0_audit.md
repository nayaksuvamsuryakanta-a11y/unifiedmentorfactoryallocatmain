### 2.4 The one functional defect found and fixed

`simulation.candidate_moves` computed both `delta_lead` and `delta_cost` as pure linear
functions of `delta_dist`. Within a single product `total_units` is constant, so
`profit_gain` was an exact scalar multiple of `lead_gain_days`; min-max normalisation then
made `_norm(lead_gain_days) == _norm(profit_gain)`, and the priority slider evaluated to a
constant for any weight. Probe output before the fix:

```
speed_weight=0.25 -> 0.2667 / 0.2581 / 0.1912
speed_weight=0.5  -> 0.2667 / 0.2581 / 0.1912   (identical values, identical ranking)
speed_weight=0.75 -> 0.2667 / 0.2581 / 0.1912
```

Fix: `Assumptions.setup_freight_cost` maps each factory to a destination-specific
one-time qualification/retooling outlay, and `candidate_moves` applies the *net* of
destination minus incumbent. The term varies per candidate independently of haul length,
so profit impact is no longer collinear with lead gain. Probe after:

```
speed_weight=0.25 -> The Other Factory / Secret Factory / Wicked Choccy's
speed_weight=0.5  -> The Other Factory / Secret Factory / Wicked Choccy's
speed_weight=0.75 -> Secret Factory / The Other Factory / Wicked Choccy's   <-- CHANGED
```

All 15 products break the collinearity (15 of 15 profit_gain/lead_gain ratios are
non-constant). `26/26` smoke tests pass, including `test_sidebar_controls_rerender`, which
asserts all four sidebar controls change the rendered output.

## 5. Migration plan

The rebuild was executed in the order below. Nothing was deleted; superseded code was moved
to `legacy/` (12 files including `INDEX.md`). Planned and completed:

1. **Audit first, change second.** Read `data_prep.py`, `config.py`, `simulation.py`,
   `app.py` and the git tree; produced §2 and §4 before editing anything.
2. **Establish the single source of truth.** `config.DATA_PATH` resolves the real CSV;
   `test_source_file_present` pins it. Verified 10,194 rows / 18 columns, Kazookles genuinely
   in the source.
3. **Rewrite the ETL** (`data_prep.py`) with an explicit `audit` return value so every Phase 8
   datum is observable rather than inferred.
4. **Rewrite the models** (`features.py`, `models.py`) so all three estimators share one split,
   one fold schedule and one pipeline; persist with `joblib`; export per-product residual std.
5. **Rewrite the UI** (`app.py`) on `st.navigation` with `st.Page(url_path=...)`, fixing
   defects 2-5. Nine pages: EDA & Models, Factory Intelligence, Research Paper, Executive
   Summary, Methodology & Model Card, plus the four modules.
6. **Fix the slider degeneracy** (defect 1) - the last functional blocker before acceptance.
7. **Regenerate artifacts and documents** (`run_pipeline.py`) so `docs/`, `artifacts/` and
   `kpis.json` agree with the code that actually ships.
8. **Delete the stale orphan** `artifacts/model_selection.csv` (defect 6) so no artifact
   contradicts the live selection.
9. **Verify** - `scripts/smoke_test.py`, 26/26, covering every Phase 8 letter a-h.
10. **Clean up build caches** (`__pycache__`, `.pytest_cache`). Scratch files created during
    debugging were left in place where they were already committed to `master` rather than
    deleted, because they belong to prior work; only gitignored caches were removed.

### Branching decisions recorded

- **Lead time is not reconstructed.** The brief treats `(Ship Date - Order Date)` as lead time
  and the ship years are later calendar years that cannot be repaired without inventing data,
  so the difference is taken unmodified and the assertions are measured on the untrimmed
  distribution.
- **The model is deliberately not used for counterfactual lead times.** All three R² are
  negative, so the scenario engine computes `new_lead = baseline_lead + delta_distance /
  assumed_speed`. The negative values are reported verbatim, and `scenario_confidence` exposes
  them as a KPI rather than hiding them.
- **Products with no distance-reducing alternative keep an explicit retain row.** Lickable
  Wallpaper and Wonka Gum have none; without the retain row they would vanish from the
  coverage count. Coverage is therefore 15/15 = 100%, and the docs say "13 of 15 have a
  shorter route; 15 of 15 receive a recommendation row".
- **Risk is non-degenerate by construction.** Four components, the brief's fixed weights,
  fixed thresholds, and every row carrying all four components so a Low risk is a measured
  state and not an empty default.
